# 🛢️ Программный комплекс «Мониторинг объектов нефтедобычи»

Информационная система для прямой связи между диспетчерским центром и полевым персоналом. Система позволяет исключить промежуточные звенья при назначении задач и автоматизировать сбор технологических данных.

# 🚀 Основные возможности
### 🖥️ [Web-интерфейс (АРМ Диспетчера)](https://github.com/yakexerr/operator_journal_app_backend/tree/main)
*Управление персоналом:* регистрация сотрудников, отслеживание статусов (активен/уволен).
*Контроль вахты:* назначение дат смен и автоматическая блокировка доступа вне рабочего времени.
*Диспетчеризация:* мгновенное назначение задач на конкретные скважины.
*Аналитика:* просмотр детализированных отчетов и результатов инженерных расчетов.

### 📱 Мобильное приложение (Инструмент Оператора)

Offline-First: работа с локальной базой данных при отсутствии интернета.
Инженерный калькулятор: расчет гидростатического давления, эффективности насосов и объемов скважин.
Умные отчеты: автоматическая подстановка данных, если замеры проводились в течение последних 24 часов.
Прямая синхронизация: получение задач напрямую от диспетчера через защищенный канал (JWT).
# 🛠 Стек технологий
Backend: Node.js, Express.js
Database: SQLite (библиотеки better-sqlite3 для сервера и sqflite для мобилки)
Security: JWT (авторизация), bcrypt (хеширование паролей)
Mobile: Flutter (Dart) с использованием паттерна Repository
Frontend: Vanilla JavaScript (ES6+), HTML5, CSS3
# 📦 Инструкция по запуску
Для работы проекта необходимо наличие установленных Node.js и Flutter SDK.
1. Запуск сервера (Backend)
Перейдите в папку operator-app:
```
cd operator-app
```

Установите зависимости:
```
npm install
```
Запустите сервер:
```
node server
```
Сервер будет доступен по адресу http://localhost:3000
2. Запуск мобильного приложения (Frontend)
Перейдите в папку operator_app_flutter:
```
cd operator_app
```

Загрузите библиотеки:
```
flutter pub get
```

Запустите приложение:
```
flutter run
```

# 🏗 Архитектура системы
Система построена на принципе Stateless-авторизации. Сервер проверяет каждый запрос на соответствие JWT-токену, статусу активности сотрудника и временным рамкам его вахты. Вся бизнес-логика записи данных защищена транзакциями для предотвращения появления «мусорных» записей при сбоях связи.
